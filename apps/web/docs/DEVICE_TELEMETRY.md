# Device reporting

Run `npm run db:setup` once to add the `device_telemetry` table. Existing scans are preserved. The dashboard works without this migration and reports that device reporting needs setup.

The ESP32 must send an authenticated heartbeat to `POST /api/device-status` every 30 seconds and after queue changes. Use the same Bearer token as `/api/readings`, with `Content-Type: application/json`:

```json
{
  "deviceId": "soil-001",
  "batteryPercent": 74,
  "pendingScans": 3,
  "syncState": "syncing",
  "ready": true,
  "sensors": { "ph": "ok", "moisture": "ok", "temperature": "ok", "npk": "unknown" },
  "lastError": null
}
```

These are protocol example values, not readings generated by the application.

- `batteryPercent`: measured 0-100, or null when unsupported. Do not guess battery percentage from USB power.
- `pendingScans`: saved records still waiting for a matching upload acknowledgement. This is a current queue snapshot, not a lifetime offline counter.
- `syncState`: `idle` when queue is empty, `syncing` while uploading a nonempty queue, `waiting_server` while waiting to retry, or `error` when user intervention is needed.
- `ready`: the device's own acquisition readiness check. A sensor reporting `error` still shows Needs attention even when ready is true.
- Each sensor: `ok`, `error`, `not_installed`, or `unknown`. A null scan value does not establish a hardware failure.
- `lastError`: optional/null, at most 200 characters. Include the affected sensor or upload error; never include secrets.

Reports use server receipt time. Reports older than 90 seconds are stale; the web no longer treats their queue count, battery or readiness as current. If Wi-Fi or the server is unreachable, the website can only show the last report. It cannot see new offline scans until a report reaches the server.

Send heartbeats serially (wait for each response before sending the next). Retry a fresh snapshot after reconnecting. Keep each stored scan until `/api/readings` returns its matching `acknowledgedRecordId`; a heartbeat is not an acknowledgement for a scan.

The current `firmware/src/main.cpp` is a scaffold. Actual sensor acquisition, flash queue, Wi-Fi upload and battery monitoring still need firmware implementation and hardware verification.
